# IMPORTANT (corrected 2026-09-20): GitHub Pages returns 403 to Baiduspider by
# User-Agent at the origin, and a Cloudflare "Cache Everything" layer alone
# does NOT fix it — on a cache MISS Cloudflare forwards the original
# User-Agent to the origin and gets the same 403. Baiduspider is usually the
# first visitor to a given URL at a given PoP, so misses are the normal case.
# The working fix is either a Cloudflare Transform Rule that rewrites
# User-Agent on the origin fetch, or moving off GitHub Pages. Until one of
# those ships, every record below is a no-op on Baidu's side.
# See photomatcher repo, 5-cn/baidu-indexing-runbook.md
#

# Superseded homepage drafts (v3 / v3.1 / v3.2 / v3.3-video) stay reachable
# for humans and carry rel=canonical + meta noindex. LLM crawlers commonly
# ignore both, so they are disallowed per AI agent above — v3.1 and v3.2
# still lead with the retired "Surfaced." headline and must not be quoted
# back as current copy.
# Western search engines are deliberately NOT blocked from them: Google and
# Bing need to fetch the page to see its noindex tag, and blocking in
# robots.txt would leave a URL-only entry in the index instead of removing it.
# The CN engines ARE blocked from them (records above) because Baidu's
# handling of meta noindex is unreliable and a URL-only entry costs us
# nothing there — we have no CN index presence to protect.
